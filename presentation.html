02 — Problem & Vision

The Problem We Solve

😵

The Pain

  • Market data is noisy — headlines arrive in bursts
  • Price moves are visible but reasons are buried in articles
  • Non-quant teams can't translate data into decisions quickly
  • Latency between event and insight is too high
✅

Our Solution

Market Mood Ring ingests news and prices continuously, scores sentiment in a live Flink stream, stores vector embeddings for semantic retrieval, and surfaces a conversational AI interface grounded in today's actual market events.

Primary Use Cases
📰

Explain Why a Stock is Moving

Real-time headline sentiment correlated to price movement, surfaced without reading every article.

📊

Live Price & Sentiment Monitoring

72-hour interactive charts and top-20 sentiment feed across 30 stocks in a single dashboard.

🤖

Conversational AI Analyst

Ask "What's happening with NVDA today?" — the AI answers using only ingested, verified news context via RAG.

🎯

Rapid Decision Support

Reduces interpretation latency from minutes of manual reading to seconds of AI synthesis.

09 — Risk Management

Key Risks & Mitigations

Risk
Description
Mitigation
🔌
Operational
Pipeline Interruption

Local environment or network dependency failure can halt news/price ingestion, causing stale data in dashboard with no auto-recovery.

  • Add Docker health probes
  • Auto-restart policies on consumers
  • Synthetic data backfill mode for offline demo
📊
Data Quality
Sentiment False Signals

VADER analyzes headline text only — lacks full article context, may misread irony or ambiguity in financial language.

  • Add confidence banding per score
  • Source quality weighting
  • Outcome feedback loop for calibration
🤖
AI Reliability
LLM Hallucination

Llama 3 may generate plausible-sounding but incorrect market analysis if context retrieval misses or model deviates from prompt instructions.

  • Strict prompt constraints + response templates
  • Citation of retrieved context snippets
  • Prompt: "If no relevant news, admit it"
🔐
Security
Local Key Handling

API keys and DB credentials in .env files on developer machines. Open service boundaries in Docker network without authentication.

  • Move to managed secret vault
  • Scoped service accounts per component
  • Network policy hardening
10 — Performance

Scalability Outlook

Current Capacity
  • 30 tickers — lightweight real-time workload
  • 60-second polling respects Finnhub free tier
  • 72-hour data window manages storage growth
  • Works effectively for demo/portfolio traffic
Scale Blockers
  • Single Kafka broker — no partition replication
  • Single Postgres instance — no read replicas
  • No retention governance by workload tier
  • No load or soak testing evidence
  • Ollama on Windows host — GPU bottleneck at concurrent queries
Recommended Scaling Path
1
Staging + SLO Baselines

Create a staging environment. Define SLOs for pipeline latency, sentiment freshness, and dashboard load time. Establish baseline metrics before scaling.

2
Horizontal Scaling + Partitioning

Add Kafka partitions per topic, scale Flink TaskManagers, add Postgres read replica. Implement retention governance (hot/warm/cold tiers).

3
Managed Services / Kubernetes

Migrate Kafka → Confluent Cloud or MSK, Postgres → RDS, LLM → cloud endpoint. Kubernetes orchestration for sustained throughput and auto-scaling.
